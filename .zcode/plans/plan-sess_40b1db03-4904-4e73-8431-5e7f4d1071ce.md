# 计算表达式：主式先面积后 /10^6*L + 详情窗体重做（断面图 + 分项/中间量表 + 悬停高亮）

## Context

现状：多分层量的主算式是 `V1+V2-V3…`，每个分项自带 `/10^6*长度` 尾；详情弹窗是一段 `<pre>` 纯文本。目标：

1. **主算式改为先面积后换算**：`V=(S1+S2+S3-S4)/10^6*L`，分项即断面面积；
2. **详情窗体重做**：顶部嵌入断面示意图（单构件画单构件、合槽画整槽），分项与中间量改用表格，**鼠标悬停分项行时在断面图上用半透明色块高亮该分项计算的梯形范围**。

**关键边界**：`expression`（完整数值算式）/ `steps` / 基线 / MCP 的“steps 拼接≡完整算式”约定**全部不动**——主式合并只发生在展示层 `presentation()`；悬停高亮需要引擎给每个分项记录梯形几何。

## Part 1：主算式面积化（tracer.py，展示层）

- 新增 `_split_volume_tail(expr)`：识别 `(面积式)/10^s*数量尾` 形态——从右侧找**顶层** `/10^数字`，要求头部无顶层加减（湿土排水复用式 `(A)/10^6*100+(B)/10^6*100` 不命中）、s>0、尾部为 `*…` 或空。
- `_compact_terms`：多分项且**全部分项**命中同一 `(s, 尾)` 时进入合并形态：
  - 各分项改为解析**头部（面积式）**，分项符号 `V{i}` → `S{i}`（从 1 起，避开中间量已占符号）；
  - `main = (S1+S2-S3…)/10^s*数量尾`，`formula = V=…`；
  - `CompactTerm.expression` = 面积压缩式，`CompactTerm.value` = 面积式的求值（mm²，与中间量“值=式的求值”口径一致）；
  - 单分项量、无尾/尾不一致的量维持现状（V 形态）。`display_expression`（Excel 主式列、右键复制）随之变为合并形态。
- 中间量符号若撞 `S{n}`（如基础断面面积 S 与分项 S2）由分配顺序天然错开，再在分项编号时跳过已占号兜底。

## Part 2：分项几何（引擎记录梯形范围）

- `Term` 增加 `geometry: tuple | None = None`，6 元组 `(h0, h1, l0, r0, l1, r1)`：自槽底向上的深度区间 + 区间底/顶的左右缘 x（相对本体中心，m）。`QDict.add`/`add_term`/`extend` 透传。
- **groove.py**：分层发射处记录 `h0=current.v, h1=current.v+delta.v`，底宽 `±bottom/2`、顶宽 `±(bottom+2Δs)/2`（sided 版用 `(sL+sR)`）；挖方合并段给 `_Segment` 补 `z0/z1`，合并项取首段底到末段顶。
- **trench_group.py**：成员 profiles 拆存 `profiles_left`/`profiles_right`（保留 flat `profiles`）；`_member_dig_fill` 每个 [lo,hi] 区间记录 `±(本体半宽 + 该侧剖面在 lo/hi 处的 width_at 之和)`——左右缘精确（不对称坡区也正确）。
- foundation / 降水 / 公式分项不记录（悬停不高亮）。

## Part 3：详情窗体（新文件 + 两处小改）

- **新文件 `src/app/views/dialogs/expression_detail_dialog.py`**：`ExpressionDetailDialog(FramelessDialog)`（复用 frameless_dialog 通用基类与 `PrecipitationEditDialog._fit_panel_heights` 自适应先例）：
  - 顶部 `_SectionCanvas(QWidget)`：黑底旧版配色，`paintEvent` 调 section_view 抽出的绘制函数 + 半透明高亮多边形（`QColor(255,255,0,90).drawPolygon`，参照 _DropOverlay alpha 先例）；
  - **分项表**：符号 | 说明 | 算式 | 计算结果(面积)；`setMouseTracking(True)` + `cellEntered` → 行几何 → 画布高亮；
  - **中间量表**：符号 | 含义 | 代入式 | 计算结果 | 来源（只列 kind=intermediate）；
  - 底部完整数值算式（可选中复制）。
- **section_view.py**：把 paintEvent 的绘制核心抽成模块级 `draw_scene(painter, scene, center_x, origin_y, width)`（paintEvent 改为调用它）；`_Scene` 新增 `member_spans`（(element_id, center_x, depth) 每成员，_build_group_scene 的 extents 循环处填充）。
- **unit_panel.py**：`_show_group_detail` 存 `self._current_group_id`；`_merge_quantities` 的 `entry["quantities"]` 改存 `(element_id, quantity)`（`_Merged` 与 `_merged_expression_detail` 同步解包）；`_show_expression_detail` 改为打开新窗体——上下文：单构件（组员则画整槽，与 `_refresh_section_for` 口径一致）→ `_build_scene`/`_build_group_scene`；合槽父行 → 合并分项（说明带 `[构件N]` 前缀）+ 整槽场景按 element_id 定位成员；多选 → 无断面图，仅表格。
- 高亮多边形换算：单构件 `x=center_x±缘*1000*zoom, y=origin_y-h*1000*zoom`；合槽 `x=center_x+(成员center+缘)*…, y=origin_y-((h_max-成员depth)+h)*…`。
- 分项/中间量数据源：`presentation().terms/definitions`；`CompactTerm` 透传 `geometry`。

## 不动与兼容

- `expression`/`steps`/`full`/基线/MCP 序列化不变 → **基线不需重生成**；
- `expression_outline` 表格首屏不变；旧文本生成函数 `_single/_merged_expression_detail` 保留（测试与 AI 数据仍用）；
- 文档：`agent/conventions.py` 补一句“多分项主算式为 (S1+S2-…)/10^s*数量 合并形态”。
