# 多管同沟槽（合槽）功能设计

> 状态：设计稿（待评审）。旧版 1.0 无此功能，无对拍对象，需构造手算样例验证。

## 1. 背景

实际市政项目中常见：两根及以上管道同沟槽敷设（雨污双管、给水+再生水），甚至管道与
箱涵同槽。此时开挖是一个**大合槽**，土方/围护/降水按整槽计算，而垫层、基础、管材
等仍是**每根管自己的量**。现行引擎每个构件条目（Element）独立开一条槽，无法表达。

### 1.1 现状要点（与设计相关的部分）

| 位置 | 现状 | 对合槽的影响 |
|---|---|---|
| `ElementInput.size_b/size_h` | 取 `pipes[0]`（首管）推导 | 多管无法进几何 |
| `groove.groove_width` | B = 断面宽+2×(壁厚+工作面加宽+工作面)，或面宽原则沟槽宽度表值 | 合槽需重定义：中间管不算工作面，换成净距 |
| `groove.cal_groove` | 分层列表 `backfill_layers` 与梯形循环**解耦**（吃任意层列表） | 可直接复用循环，换合槽宽与并集层 |
| `foundation._found_pipe/_found_box` | 占位扣减是**同 key 负项**（垫层扣弓形、坞膀扣弓形…） | 逐管扣减与合槽公共量经 QDict 同 key 合并，架构天然支持 |
| `QDict.add` | 同 key 累加 | 合槽公共层 + Σ逐管扣减 直接叠加 |
| 一个 Element 多根 Pipe | 只是管材量（含量），不参与几何 | 合槽不沿用此机制，另立分组 |

## 2. 总体思路：合槽编组（Trench Group）

**用户先按现有流程逐个录入构件（直埋管/包封管/箱涵…），再把同一单位工程内、沟槽相邻
的若干条构件"编组"为一个合槽组。**

- 组 = 一个虚拟大断面：整槽挖方/回填/围护/降水/支撑/特殊地基按**合槽几何**算一次，
  输出挂在**组**名下；
- 组员 = 各自保留：垫层/管道基础/包封/箱涵本体/管材等**逐管量**，挂各构件名下，
  按各自数量放大；
- 组内顺序（`order_no`）即**从左到右**的水平排列。

### 2.1 候选方案对比

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 编组（推荐） | 现有 Element 不动，加 `group_id` 关联成组 | 复用录入/详情/构件库/AI 全部现有流程；计算加一条合槽路径 |
| B. 新"合槽构件"类别 | 一种容器构件内嵌子构件 | 嵌套编辑 UI、规格、构件库、迁移全要重做一轮，代价大 |
| C. Element 加净距/相对位置字段但不分组 | 松散表达 | 无组级归属（土方挂谁名下？），汇总与断面图都别扭 |

## 3. 用户表达（交互）

1. **编组**：录入表格多选若干行 → 右键「合槽编组」。约束（见 §8）不满足时弹窗说明。
2. **表格呈现**：组员强制连续显示，行首画组色条/组名；组头行可编辑**组名、默认管间净距**。
   组员行新增一列「左净距」(m)（首管无此项；留空 = 组默认净距；存字符串原文，可写算式，
   与埋深/数量同风格）。
3. **组属性**：详情面板显示组的汇总信息（成员规格串、合槽底宽/深预览、统一的原则引用）。
   编组后组员的 **pe/pf/pp/pw 显示为组统一值（取主构件 = 组内第一条），编辑置灰**；
   计算也只用主构件的原则——一个槽里两套放坡/回填材质无法计算。
4. **成员维护**：右键「加入合槽…」（选已有组）/「移出合槽」「解散合槽」「组内左移/右移」。
5. **断面图**：选中组（或任一组员）时画合槽断面：整槽梯形 + 各成员本体按水平偏移摆放。
6. AI/MCP：新增合槽组增删改查工具，与界面同走 `viewmodels/unit_vm` 模块级函数（一条代码路径）。

## 4. 数据模型

```
trench_group                    # 合槽组
  id, unit_id(FK), name,        # 组名（清单项目特征用）
  default_gap(String 原文),      # 默认管间净距 m（可算式）
  order_no

element 增列:
  group_id  -> trench_group.id  # nullable；组内 order_no 即左右顺序
  left_gap  String              # 左净距原文（空=组默认；首管忽略）
```

- stn JSON 体加版本号，编解码器同步；旧工程迁移 = 全部无组，行为不变。
- undo 是整工程快照，天然兼容。锁/备份/自动保存不受影响。
- 顶管、牵引管、附属构筑物**不可入组**（不开槽/不参与沟槽）。

## 5. 计算引擎

### 5.1 合槽几何

记组员 i（从左到右）的"基础外皮宽"（= 单管槽底宽去掉两侧工作面）：

```
b_i = size_b_i + 2*(t_i + a_i)/1000        # 直埋；包封/箱涵 = 断面宽 + 2*工作面加宽/1000
```

```
B_合 = Σ b_i + Σ gap_i + (workwidth_左 + workwidth_右)/1000
H_合 = max_i ( depth_i + (换填 + t_i + c1_i)/1000 )
```

- 两侧工作面取**最外侧两管**按各自工作面宽度表查得的值；
- 面宽原则 `groove_width == B`（沟槽宽度表）时**不适用**于合槽：表值是单管槽宽语义，
  合槽一律按上式推算（文档与 UI 提示）；
- 算式不做预运算原则照旧：`B_合` 的算式把每根管的 `管径/1000+2*(壁厚+工作面加宽)/1000`、
  每条净距、两侧工作面全部写全，与现有 `Dim` 拼法一致。

### 5.2 挖方与回填：并集分层 + 逐管扣减（核心）

**分层界面取并集**：对每根管沿用现有 `backfill_layers` 的界面推导（垫层顶、管中心、
管顶、管顶+0.5），全组界面**取并集后切层**；每层一条梯形（合槽底宽 B_合、该层高、
当前围护级放坡），挖方段合并规则与现状相同。

**每层回填材质规则（一句话）**：该层区间落在哪根管的功能带内就归哪层
（坞膀下半 dock_l / 坞膀上半 dock_h / 管顶50 cover50 / 覆土 cover）；与多根管的功能带
相交时，**取回填要求更高的带**（坞膀 > 管顶50 > 覆土，即砂类优先）——偏安全、与
手算习惯一致，规则可解释。换填层（PF）组内统一，同现状。

```
合槽挖方   = Σ 并集层梯形(B_合)
合槽回填正量 = Σ 并集层梯形(B_合) 按上述材质归类
逐管扣减   = 对每根管跑现有 _found_pipe / _found_encased / _found_box 的负项
             （垫层扣弓形/基础、坞膀扣弓形、上半扣半圆…，各用各的图集参数）
逐管正量   = 垫层、砼基础、模板、包封、箱涵本体/钢筋…（现状函数不动）
```

扣减与合槽正量是**同 key 负项**，`QDict` 自动合并——这正是现有单管
"分层回填正量 − 管占位"模式的多管推广，实现上是逐管调用 + 一次合槽层循环。

**实现落点**：`cal_groove` 重构出"接受自定义层列表与自定义底宽"的入口
（现循环本就解耦），新增 `cal_groove_multi(group)` 组装并集层；单构件路径不变。

### 5.3 异深（组员埋深不同）

第一期只做**统一槽底**：整槽挖至 H_合（最深管的槽底）；浅管基础底与槽底之间的高差
Δh_i，按"超挖回填"出量（材质默认取该管垫层材料，组属性可改）。这是雨污双管等
常规做法，量偏安全。阶梯槽（各挖各深、台阶放坡）列为后续增强。

### 5.4 降水 / 围护 / 支撑 / 特殊地基

全部以 **H_合、B_合** 为输入（选做法 `choice_work(pe, H_合)`、井点布置按合槽宽、
围护公式代入 `width = B_合`）。需要把 `precipitation.cal_precipitation` /
`works_quantities` 中隐式取用的 `info.size_b` 显式参数化为"槽宽"入参（单管路径传原值，
行为不变）。

### 5.5 数量与汇总归属

- 合槽公共量（挖方/回填/垫层扣减/降水/围护/支撑/特殊地基）挂**组**名下，
  项目特征 = 成员规格串（如 `Dn600+Dn1200 合槽`），× 组计算长度 L_组；
- 逐管量挂**各构件**名下 × 各自 amount；
- **L_组 = 组员 amount 必须一致**（编组时校验；不一致则提示先统一——"局部合槽/起止
  桩号不同"列为远期，需另设分段模型）。

### 5.6 输出算式示例（示意，数字为编造）

```
开挖|Ⅲ类土|m3
  (2*(600/1000+2*(65+130)/1000)+0.4+1000/1000+2*(80+150)/1000+2*500/1000
   +2*(3.1+0.465)*1)*(3.1+0.465)/2 * 120.5
回填|中粗砂|m3   （合槽梯形层 − Σ各管弓形/半圆占位，同 key 合并成一条）
管材|Ⅱ级混凝土管 Dn600|m   1*120.5
管材|Ⅱ级混凝土管 Dn1000|m  1*120.5
```

## 6. 断面图

`_build_trench_scene` 增加合槽分支：层段来自并集分层（复用 `_walk_layers`），
本体图形 = Σ `_ontology_shapes(member)` 按累计偏移 `Σ b_j + Σ gap_j` 摆放；
异深时浅管画"超挖回填"填充区。选中组或多选组员时展示（`show_multi` 已有入口）。

## 7. 汇总 / 导出 / AI / MCP

- `summary` 汇总口径不变（QDict 合并 × 单价），组量与成员量自然并入；
- Excel 导出：组行项目特征用组名+成员规格串，表达式列照旧；
- AI/MCP 新增 4 个组工具（创建/解散/改属性/成员调整），写操作确认窗同现有策略；
- 构件库插入流程不变（插入后手动编组）。

## 8. 校验规则（编组与运行时）

1. 组员 ∈ {直埋、包封、箱涵、管廊}；顶管/牵引管/构筑物拒绝；
2. 同一单位工程内；跨 unit 拒绝；
3. 组员 pe/pf/pp/pw 一致（以主构件为准，编组时不一致则提示，编组后置灰统一）；
4. 组员 amount 一致（否则警告并拒绝计算组公共量）；
5. 净距 < 某最小值时黄色预警（不阻断——规范最小净距由用户按设计保证）；
6. 沟槽宽度表面宽原则（groove_width==B）在组上提示"合槽按推算法"。

## 10. 待决策点（已给推荐，可推翻）

1. **材质冲突规则**：并集层与多管功能带相交时"高要求带优先"（推荐）vs 按"最浅管"控制；
2. **异深策略**：统一槽底+超挖回填（推荐，第一期）vs 阶梯槽；
3. **L_组**：强校验组员 amount 一致（推荐第一期）vs 组上独立存长度；
4. **净距输入位置**：构件行「左净距」列（推荐）vs 组属性里逐缝表；
5. **沟槽宽度表**：合槽不适用（推荐，直接推算法）。

## 11. 风险

- 无旧版对拍：第一期必须配 2~3 个手算断面（双管等深 / 双管异深 / 管+箱涵）做金样例测试；
- `works_quantities` 修正史（width 混单位 bug）提示：合槽宽度入参改造时注意单位
  （B_合是 m，公式代入处现状一致，勿再引入 mm/m 混算）；
- 单构件回归：合槽路径必须完全独立，`compute_element` 单构件行为逐字节不变（对拍现有
  回归样例）。
