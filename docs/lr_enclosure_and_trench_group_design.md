实现口径与 §6 的两处偏差（均已按三期方案提前落定）：

1. **支撑拆行取代"每侧调用 + 双算预警"**：库模板支撑公式拆成贯通行（无 sides）与
   围檩行（含 sides），同定额键合并；公式键统一为 `FA~FZ`，支撑行由显示名类别
   `支撑|…` 识别，分设 / 合槽按"围檩每侧 ×1、贯通支撑整槽一次（左优先）"分流
   （`component_side_quantities`），两侧同原则分设的支撑总量与普通单原则严格一致；
2. **合槽几何用逐构件宽度剖面 + 标高分层梯形**：每根管按自己的分层界面与
   材质管自己的宽度剖面（与"子节点只影响自身范围"的编组语义一致）；回填
   分层界面、各侧放坡分级 / 平台折点、相邻槽底标高合并成标高事件集，事件
   之间宽度线性，单层面积一律按梯形计算（恒宽层退化为矩形）。

## 1. 背景与两个场景

**场景一（单管分侧）**：单根管的沟槽左右两侧围护形式不同——一侧临建筑物/道路/河道
打钢板桩（或 SMW、灌注桩）支护、开阔侧放坡；或两侧坡度不同；或两侧都支护但型式不同。

**场景二（合槽编组）**：两根及以上管道同沟槽敷设（雨污双管、给水+再生水）。开挖是
一个大合槽，土方/围护按整槽算；垫层、基础、管材是每根管自己的量。

两个场景共用同一套地基——**沟槽断面按"面"拆分，每个面归属一条围护原则**：

* 单管分侧（退化的两段）：`[左边坡·左PE] [左工作面] [构件] [右工作面] [右边坡·右PE]`
* 合槽编组（n+1 个面）：`[左边坡·首构件左PE] [左工作面·首构件自身PW] [构件1]
  [相邻区1] [构件2] … [构件n] [右工作面+右边坡·末构件右PE/自身PW]`
  相邻区等深 = 两侧各自工作面平接（两侧围护均 "-"）；异深 = 浅侧自身工作面
  + 深侧所选原则向浅槽底放坡，坡与浅槽底交点即浅侧虚拟垂直围护的位置。

## 3. 总体思路：构件级左右原则 + 合槽父子编组

1. **构件引用左右两条 PE**：`element` 新增 `pe_left_name` / `pe_right_name`；
   主表格「沟槽围护原则」下拉新增特殊项 **「左右分设」**（措辞已评审确定），选中后
   `pe_name` 存该占位文本（同 1.0 多原则占位机制），详情面板出现「围护原则」tab。
   普通构件（`pe_name` = 具体原则名）行为逐字节不变。
2. ~~**公共参数按侧取用**~~（**v10 起废弃**）：挖填类型（开挖土质/回填材质）已
   迁到**挖填降水原则**（原降水措施原则改名）、管道基础（砼基础/角度/垫层）已迁到
   **地基处理原则**——一个构件只引用一条挖填降水原则与一条地基原则，因此这两项
   不再需要"取侧"，左右分设只体现在围护做法上。
3. **支撑按侧开关**：左侧支撑/右侧支撑两个勾选，控制两侧类别为「支撑」的公式
   是否参与计算。
4. **合槽编组**：多选构件编组后插入一条**父节点行**（合槽组），被选构件成为其
   **子节点**；组内构件从上到下 = 沟槽从左到右（上下移动即左右排序）。
   **父节点不选围护 / 面宽原则**（表格中显示 "-"，也零工程量）。组员全部强制
   左右分设（规则 2），原则按面归属：
   * 合槽左边坡 = **首构件（表格最上面）的左侧原则**；右边坡 = **末构件（最下面）
     的右侧原则**（规则 3）；
   * 每个构件的工作面宽按**自己的面宽原则**查表（规则 6）；
   * 相邻两构件**埋深相同**（埋深 + 基础厚度等推导后的实际槽深）时，两侧相邻面
     围护均强制 "-"（等同 1:0、高 0 的围护，规则 4）；
   * 相邻两构件**埋深不同**时，深侧构件的相邻面围护由用户选择（默认当前围护
     原则列表第一条），按所选原则向浅侧槽底放坡；浅侧构件的相邻面强制 "-"，
     按自身面宽原则配工作面 + 虚拟垂直空围护（规则 5）；
   * 挖填工程量默认以**更浅一侧构件的虚拟垂直围护**为拆分线（规则 7）。
5. **公式单面化**：库模板 `*2` → `*sides`；普通构件代入 `sides=2`（输出与现状
   逐字节一致），分侧/合槽的每个面代入 `sides=1`。

## 4. 用户表达（交互）

### 4.1 单管左右分设（参照 1.0 多围护原则的界面形式）

1. **入口**：主表格「沟槽围护原则」下拉末尾新增「左右分设」（与 1.0
   "多围护原则"占位项同位置同机制）。选中后：
   * 主表格该列显示「左右分设」；
   * 详情面板在「工程量」tab 右边出现 **「围护原则」** tab（未选分设时该 tab 不显示）。
2. **「围护原则」tab**（一张两列表格，行头 + 值）：

   | 行头 | 控件 |
   |---|---|
   | 左侧围护 | 下拉：全部围护原则（与主表格下拉同源，**不含**「左右分设」项） |
   | 右侧围护 | 下拉：同上 |
   | 左侧支撑 | 勾选框（默认勾选）：勾选 = 计算类别为「支撑」的公式，不勾 = 不算 |
   | 右侧支撑 | 勾选框（默认勾选） |

   （v10 起本 tab 只有上面四行：挖填类型归挖填降水原则、管道基础归地基原则，
   不再因左右围护不一致而需要"取侧"。）
3. **退回普通模式**：主表格「沟槽围护原则」改选任一具体原则 → 左右字段清空，
   「围护原则」tab 消失。
4. **断面图**：左右边线各按各侧原则的做法（级划分/坡度/桩面）绘制。

### 4.2 合槽编组

1. **编组**：主表格多选若干行 → 右键「合槽编组」（约束见 §9）。编组后：
   * 被选构件位置最前处插入一条**父节点行**，全部被选构件成为其子节点（缩进、
     可折叠）；组内构件从上到下即从左到右；
   * **父节点不选围护 / 面宽原则**（规则 1）：主表格「沟槽围护原则」「工作面宽
     原则」两列显示 "-"，无下拉框；
   * **每条子节点强制左右分设**（规则 2）：主表格「沟槽围护原则」列只读显示
     「左右分设」；首构件左侧 / 末构件右侧保留编组前原则（规则 3），其余内侧
     默认当前围护原则列表第一条（规则 5；等深时计算强制 "-"）；
   * （v10 起已无「挖填类型」「管道基础」取侧行：两项归各自原则，与左右围护无关。）
2. **父节点行**：名称与数量（L_组）可编辑；「地基处理原则」「降水原则」「围护原则」
   「工作面宽原则」均显示 `-`。**父节点埋深恒显示 `-`、不参与任何计算**
   （`depth_value = 0`；组内槽深全部由各子构件自己的埋深推导）。**数量 L_组 由父
   节点唯一持有**：父行可改，修改后强制同步全部子构件；子行数量只读（置灰，提示
   “由父节点统一控制”）。编组 / 加入组时不再校验组员数量是否一致，统一取父节点
   数量。父节点**不产生任何工程量行**，在汇总 / 导出 / 详情面板中仅作为下属子构件
   工程量的合计分组行。
3. **子节点行**：「围护原则」tab 中左右侧的**可编辑性由槽深比较动态决定**：
   * 首构件的左侧、末构件的右侧恒可编辑（合槽外边缘，规则 3）；
   * 中间侧：只有**比相邻构件更深**时才可编辑（深侧放坡原则，规则 5）；
     等深 / 更浅的一侧显示 `-` 且下拉框禁用，对应的支撑勾选同步禁用；
   * 改变埋深后重载单位工程会重建该 tab（`_refresh_grouped_lr_tab`）；
   * 子节点自己的「工作面宽原则」决定自己的工作面宽（规则 6），父节点不参与。
4. **成员维护**：右键「加入合槽…」「移出合槽」、「解散合槽」（父节点删除、
   子节点还原）；移出 / 解散与复制到组外同口径：两侧均为 `-` 取项目第一条
   围护原则，单侧 `-` 取另一侧，两侧都有效则保留左右分设（含侧原则与支撑
   勾选）。组内上移/下移 = 左移/右移（复用现有 move_element 交互）。
5. **断面图**：选中父节点或任一子节点均画**整槽全景断面**（首构件左原则 /
   末构件右原则 + 各构件本体与自身工作面 + 异深内侧坡），见 §7。

## 5. 数据模型

```
element 增列:
  pe_left_name     String(200)  左侧围护原则名（空 = 普通单原则模式，现状语义）
  pe_right_name    String(200)  右侧围护原则名
  support_left     Boolean      左侧支撑是否计算，默认 True
  support_right    Boolean      右侧支撑是否计算，默认 True
  group_id         -> trench_group.id   nullable；组内 order_no 即左右顺序

（v10 起删除 ``excvt_side`` / ``foundation_side`` 两个取侧列：挖填类型归
  挖填降水原则（``principle_precipitation.excvt/dock_l/dock_h/cover50/cover``）、
  管道基础归地基原则（``principle_foundation.con_found/found_angle`` + 垫层表
  ``foundation_cushion``）。旧文件里的这两列读取时忽略。）

trench_group（父节点）:
  id, unit_id(FK), name, order_no,
  amount           # 合槽计算长度 L_组（唯一数量来源；子构件 amount 强制等于此值）
  pe_name          # 恒空（父节点不选围护原则；旧工程兼容保留）
  pw_name          # 恒空（父节点不选面宽原则；旧工程兼容保留）
```

* 父节点**无埋深字段**：埋深恒显示 "-"、`depth_value = 0`，不参与几何（组内
  各构件槽深由子构件自己的埋深推导）。
* **占位机制**：左右分设模式下 `pe_name` 存 `LR_PE_TEXT = "左右分设"`（新常量，
  对应已删的 1.0 `MULTI_PE_TEXT = "多围护原则"` 先例）；`resolve_element_principles`
  的按名回退逻辑跳过占位名，改读左右列。
* stn JSON 体版本 2 → 3：element 新列 + `trench_group` 表（含 `amount`）+ `group_id`，
  全部可缺省（读 v2 文件 = 无分侧无编组，行为不变；旧工程 `group.amount` 缺省时
  取首个组员数量兜底，并强制对齐全部组员）；编解码器同步。
* undo 是整工程快照，新表/新列随快照复制（补一条含新列的回归用例）；
  锁/备份/自动保存不受影响。
* **原则库（PE/PF/PP/PW 表结构）与 FormPE 编辑器零改动**——分侧只是引用方式变化，
  这是构件级方案相对做法级方案的最大工程红利。

## 6. 计算引擎

### 6.1 库公式 `sides` 变量（贯穿两个场景）

Ei 库模板全部 `*2` → `*sides`（喷锚 FA~FD、横列板/灌注桩/SMW 的 F 与围檩项；
放坡模板本就无公式）；`engine.pre_sub` 增加第四代入变量（公式无该变量时零影响）：

* 普通构件：`sides=2` 代入，输出算式里就是 `*2`，**与现状逐字节一致**；
* 分侧/合槽的每个面：`sides=1`，得单面量；
* 存量工程公式（用户副本仍带 `*2`）不自动改写：普通模式语义本就两侧、照旧正确；
  左右分设是**新建引用**（从库模板语义出发），见 §6.2 的取值路径。

### 6.2 单管左右分设

* **两侧独立选做法**：`choice_work(pe_left, groove_depth)` 与
  `choice_work(pe_right, groove_depth)` 各自进行（同一深度）。
* **不对称几何**：梯形 `(2B + H*sL + H*sR)*H/2`；层间外扩 `Δ*sL + Δ*sR`；平台加宽
  只加发生切级的一侧；层循环按**两侧级标高的并集**切段，每段 `(sL, sR)`；
  挖方段合并判据从"坡度相等"改为"(sL,sR) 相等"。`trapezoid_expr` 直壁侧省略该项
  （右侧桩：`(2*B+H*0.5)*H/2`；两侧直壁仍 `B*H`）。普通构件走原单套循环路径，
  逐字节不变（两条路径共用底层梯形函数）。
* ~~**公共参数取侧**~~（**v10 起废弃**）：开挖土质/回填材质统一取构件引用的挖填降水
  原则 `pp`；砼基础/基础角度/垫层统一取构件引用的地基原则 `pf`（`build_atlas_query`
  第二参由围护原则改为地基原则），**图集查询与候选参数匹配（match_atlas_candidates）
  同用 pf**，不再分侧。
* **档位匹配**：围护与支撑共用同一个做法，按**含换填层厚度**的槽深匹配档位；
  匹配后一次代入该做法下的全部公式（`FA~FZ`，不区分围护 / 支撑）。
* **围护行（类别 `围护`）**：每侧 work 的各级构件 + 止水各调一次，`sides=1`；
  放坡侧模板无公式，天然不出量。
* **支撑行（类别 `支撑`）**：`support_left` 勾选 → 左侧 work 的支撑公式参与
  （`width` 代入槽底宽 B、`sides=1`）；`support_right` 同理。两侧都勾且两 PE
  相同 = 现状两侧总量，数值自洽。
* **换填层**（用户强调点）：PF 换填层的梯形同层循环取 `(sL, sR)`——换填层开挖/
  回填量自动反映两侧不同放坡系数。
* **降水 / 特殊地基**：`pp` 原则不变（井型"侧数"参数由用户按实际布置设置）；
  特殊地基公式 `width=B` 不变。湿土排水的 `cal_groove(depth-1)` 副调用自动
  继承不对称几何。

### 6.3 合槽编组

**原则归属（规则 1–6）**：

* 父节点 PE/PW 恒空，不参与计算与几何（规则 1）；
* 组员全部 `pe_name = 左右分设`（规则 2）；首构件左侧 / 末构件右侧决定合槽
  外边缘（规则 3），中间面只有**更深一侧**生效；
* 每个构件的工作面宽 `w_i = workwidth_of(构件 i 自己的 PW, 构件 i 的管径)`
  （规则 6）。

**几何（区间模型，从左到右拼接）**：

```
B_平底 = w_1 + Σ b_i + Σ g_i + w_n
  b_i = 构件 i 基础外皮宽（= 单管槽底宽去掉两侧工作面）
  w_i = 构件 i 自身面宽原则匹配到的工作面宽
  g_i = 相邻区宽度（构件 i 与 i+1 之间）
      = 等深：w_i + w_{i+1}（两侧各自工作面平接，两侧围护均为 "-"）
      = 异深：w_浅 + w_深 + run_i（浅侧自身工作面 + 深侧自身工作面 + 深侧放坡水平投影）
H_i = 构件 i 实际槽深（埋深 + 换填 + 壁厚 + 垫层，各自推导）；H_合 = max H_i
```

* **等深**（相邻 H_i 相同，规则 4）：整槽平底；相邻两侧围护强制 "-"，等同
  1:0、高 0 的围护，不产生围护 / 支撑量；
* **异深**（规则 5）：各构件挖至各自 H_i。深侧构件相邻面围护由用户选择
  （默认围护原则列表第一条），`choice_work(深侧 PE, ΔH)` 向浅侧槽底放坡，
  水平投影 `run_i` 逐级累加（含切级平台）；坡与浅槽底的交点即**浅侧虚拟垂直
  空围护**的位置（浅槽底以上竖直面）。浅侧构件相邻面强制 "-"，按自身面宽
  原则取工作面宽，与虚拟垂直围护相贴。深侧为桩类时 run=0，即两槽间竖直隔断。

**挖填拆分（规则 7，以浅侧虚拟垂直围护为分界）**：

```
浅侧构件：本体 b_i + 自身两侧工作面（相邻侧到虚拟垂直围护为止）
深侧构件：浅槽底以上竖直条带（宽 w_深 + run）
          + 坡楔（h_浅 处宽 run → h_深 处宽 0，坡从自身工作面外缘起算）
          + 自身共享侧工作面 w_深
          + 本体 b_i + 自身另一侧工作面 / 外边缘
等深相邻：两构件各得自己的工作面矩形，分界为两工作面的公共边
```

**按标高分层（现行算法）**：把每个构件自己的回填分层界面（换填顶、垫层顶、
坞膀下半顶、坞膀顶、管顶 50cm 顶、覆土顶）与各侧放坡剖面的全部分级 / 平台
折点（含左右相邻构件的槽底标高）合并为标高事件集；相邻事件之间宽度线性，
单层断面面积按梯形 `(2*w_下+ΣH*s)/2*Δh` 计算（恒宽层退化为 `w*Δh`）。放坡
系数变化处、平台跳变处都正好落在事件边界上，因此每一层都是一个梯形。

分层回填按各层梯形面积归类到该构件自己的 `backfill_layers` 层名；降水折减
宽度、特殊地基 `width` 用该构件归属带宽 `flat_width`（本体 + 两侧归属区）。

**围护量（每面 ×1）**：

```
左边坡 → 首构件（其左原则）        右边坡 → 末构件（其右原则）
相邻区异深 → 深侧构件（其朝向该面的原则）   等深相邻 → 不出围护量
```

`sides=1`、`width` 代入 `B_平底`。支撑勾选语义 = 该构件**朝向该面**的勾选：
首构件的左侧支撑 → 左边坡；末构件右侧支撑 → 右边坡；中间坡由深侧构件朝向
该面的勾选控制（深侧为右邻用其左侧支撑，为左邻用其右侧支撑）。

**降水 / 特殊地基 / 基础 / 管材**：逐构件、挂各自名下；挖填类型取子构件引用的
挖填降水原则 `pp`、管道基础取地基原则 `pf`（v10 起；原先的 `excvt_side` /
`foundation_side` 取侧已删除）。

**父节点零工程量**：全部输出挂在子构件名下，父节点仅作合计视图；每条构件量
× L_组（**L_组 由父节点唯一持有**：`trench_group.amount`，子构件 `amount` 强制
等于父节点值，父行可改、子行只读）。父节点**埋深不参与几何**——各 `H_i` 全部
来自子构件自己的埋深推导。

1. 左右分设：两 PE 必选；「左右分设」占位名不可作为左/右原则；支撑允许全不勾

3. 父节点**不选围护 / 面宽原则**（表格两列显示 "-"、无下拉框；`update_group`
   只接受名称 / 数量）；父节点埋深恒 `-`、不参与计算；子节点 `pe_name` 恒为
   「左右分设」，不可改回具体原则（更改只作用于左 / 右分设字段）；
4. 子节点侧面可编辑性由**槽深比较**动态决定（`group_side_plan`）：首构件左侧 /
   末构件右侧恒可编辑（合槽外边缘）；其余侧只有**比相邻构件更深**时可编辑
   （即深侧放坡原则）；等深 / 更浅的一侧下拉只有 "-" 且禁用，对应支撑勾选
   同步禁用；改变埋深后重载单位工程会重建该 tab（`_refresh_grouped_lr_tab`）；
5. 面宽原则的"沟槽宽度表"模式（groove_width==B）不适用于合槽（表值是单管
   槽宽语义），合槽一律查**工作面宽度表**，每条构件按自身原则取自身工作面宽
   （文档与 UI 提示）；
6. 合槽内子节点的挖填类型 / 管道基础一律走子构件**自身引用**的挖填降水原则
   （`pp`）与地基原则（`pf`），与左右围护无关（v10 起取侧行已删除）。

## 12. 风险

* **公式改版回归**：库模板 `*2`→`*sides` 后，普通构件输出算式必须与现有基线
  逐字节一致（`tests/baselines/对拍工程.json` 全量对拍 + `sides` 代入单测）；
* **几何双路径退化一致性**：普通构件走原单套循环、分侧才走并集路径，两路径共用
  底层梯形函数，浮点递推顺序保持一致；
* **主表格树形化是 UI 大改**：现平铺 `ElementRow` 源要混排 `trench_group` 父行 +
  缩进子行 + 折叠，选中/右键/移动/复制原则等既有交互都要适配父子结构；
* **B_平底 算式长度**：全来源展开（wL/Σb/Σg/wR + 两侧坡）后算式很长，与现有
  `Dim` 拼法一致性、Excel 可粘贴性需对拍；
* **异深中间坡几何**是本计划最复杂的一块（槽底折线 + 标高分层梯形），现已用
  逐构件宽度剖面 + 标高事件集统一落地（等深 / 异深同一路径），`run` 由深侧
  放坡系数推导，不再存在"用户间距不足导致坡面侵占"的校验项；
* **无 1.0 对拍**：一/二期各配 2~3 个手算断面金样例（单管左坡右桩、双管等深
  合槽、双管异深中间坡）；
* **父节点零工程量约束**：`compute_group` 的输出直接按构件分桶，汇总 / 导出 /
  详情面板各处不得给父节点挂量（父行只是合计视图）——实现时以"父节点无
  QDict 行"作为硬校验；
* **父节点 L_组 / 埋深约束**：子构件 `amount` 恒等于 `trench_group.amount`
  （父行编辑后同步、子行只读，旧工程打开时由首成员兜底对齐）；父节点无埋深，
  任何路径都不得把父节点埋深带入 `H_i` 推导。
* **合槽路径完全独立**：`compute_element` 单构件路径逐字节不变（对拍现有回归样例）。
