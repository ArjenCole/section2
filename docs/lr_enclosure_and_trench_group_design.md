实现口径与 §6 的两处偏差（均已按三期方案提前落定）：

1. **支撑拆行取代"每侧调用 + 双算预警"**：库模板 Z 类拆成贯通行（无 sides）与
   围檩行（含 sides），同定额键合并；分设 / 合槽按"围檩每侧 ×1、贯通支撑整槽
   一次（左优先）"分流（`component_support_quantities`），两侧同原则分设的支撑
   总量与普通单原则严格一致；
2. **合槽几何用逐构件带积分取代并集分层**：每根管按自己的分层界面与材质管
   自己的归属区（与"子节点只影响自身范围"的编组语义一致），比其槽底更深的
   归属区（中间坡楔形）追加为覆土层；功能带优先级规则因横向分区而天然不再需要。

## 1. 背景与两个场景

**场景一（单管分侧）**：单根管的沟槽左右两侧围护形式不同——一侧临建筑物/道路/河道
打钢板桩（或 SMW、灌注桩）支护、开阔侧放坡；或两侧坡度不同；或两侧都支护但型式不同。

**场景二（合槽编组）**：两根及以上管道同沟槽敷设（雨污双管、给水+再生水）。开挖是
一个大合槽，土方/围护按整槽算；垫层、基础、管材是每根管自己的量。

两个场景共用同一套地基——**沟槽断面按"面"拆分，每个面归属一条围护原则**：

* 单管分侧（退化的两段）：`[左边坡·左PE] [左工作面] [构件] [右工作面] [右边坡·右PE]`
* 合槽编组（n+1 个面）：`[左边坡·父节点PE] [左工作面·父节点PW] [构件1] [中间坡1·子1右PE]
  [构件2] … [构件n] [右工作面+右边坡·子n右PE/PW]`

## 3. 总体思路：构件级左右原则 + 合槽父子编组

1. **构件引用左右两条 PE**：`element` 新增 `pe_left_name` / `pe_right_name`；
   主表格「沟槽围护原则」下拉新增特殊项 **「左右分设」**（措辞已评审确定），选中后
   `pe_name` 存该占位文本（同 1.0 多原则占位机制），详情面板出现「围护原则」tab。
   普通构件（`pe_name` = 具体原则名）行为逐字节不变。
2. **公共参数按侧取用**：挖填类型（开挖土质/回填材质）、管道基础（砼基础/角度/垫层）
   各自通过一个"取侧"下拉指定按左侧还是右侧原则计算——一个构件只能有唯一的
   挖填类型与管道基础计算原则。
3. **支撑按侧开关**：左侧支撑/右侧支撑两个勾选，控制两侧 Z 类（支撑/围檩）公式
   是否参与计算。
4. **合槽编组**：多选构件编组后插入一条**父节点行**（合槽组），被选构件成为其
   **子节点**；组内构件从上到下 = 沟槽从左到右（上下移动即左右排序）。
   父节点 PE/PW 只负责**最左一侧**（左边坡 + 左工作面）；每条子节点的 PE/PW 只负责
   **自己右边一侧**（与右邻构件间的中间坡围护 + 间距）；最右子节点的右 PE/PW 即
   合槽右边缘。子节点的地基（PF）与降水（PP）只影响当前节点范围。
   **父节点不持有任何工程量**——全部工程量分到子构件名下，父节点仅作合计视图。
5. **公式单面化**：库模板 `*2` → `*sides`；普通构件代入 `sides=2`（输出与现状
   逐字节一致），分侧/合槽的每个面代入 `sides=1`。

## 4. 用户表达（交互）

### 4.1 单管左右分设（参照 1.0 多围护原则的界面形式）

1. **入口**：主表格「沟槽围护原则」下拉末尾新增「左右分设」（与 1.0
   "多围护原则"占位项同位置同机制）。选中后：
   * 主表格该列显示「左右分设」；
   * 详情面板在「工程量」tab 右边出现 **「围护原则」** tab（未选分设时该 tab 不显示）。
2. **「围护原则」tab**（一张两列表格，行头 + 值）：

   | 行头 | 控件 |
   |---|---|
   | 左侧围护 | 下拉：全部围护原则（与主表格下拉同源，**不含**「左右分设」项） |
   | 右侧围护 | 下拉：同上 |
   | 左侧支撑 | 勾选框（默认勾选）：勾选 = 计算 Z 类公式，不勾 = 不算 |
   | 右侧支撑 | 勾选框（默认勾选） |
   | 挖填类型 | 下拉：按左侧原则 / 按右侧原则（默认按左侧） |
   | 管道基础 | 下拉：按左侧原则 / 按右侧原则（默认按左侧） |

   「挖填类型」= 该侧 PE 的开挖土质 + 坞膀/管顶50/覆土回填材质（对应 FormPE
   "挖填类型"框）；「管道基础」= 该侧 PE 的砼基础开关 + 基础角度 + 垫层材质/厚度
   （对应 FormPE"管道基础"框，同时决定图集查询与候选参数匹配）。
3. **退回普通模式**：主表格「沟槽围护原则」改选任一具体原则 → 左右字段清空，
   「围护原则」tab 消失。
4. **断面图**：左右边线各按各侧原则的做法（级划分/坡度/桩面）绘制。

### 4.2 合槽编组

1. **编组**：主表格多选若干行 → 右键「合槽编组」（约束见 §9）。编组后：
   * 被选构件位置最前处插入一条**父节点行**，全部被选构件成为其子节点（缩进、
     可折叠）；组内构件从上到下即从左到右；
   * **每条子节点自动转为左右分设构件**：`pe_left` / `pe_right` 均置为原 `pe_name`
     （合槽内只有右原则参与计算，左侧行在 tab 中置灰，见下）。
2. **父节点行**可编辑：名称、「沟槽围护原则」（左边缘 PE）、「工作面宽原则」
   （左边缘 PW）；「地基处理原则」「降水原则」显示 `-` 且不可选。埋深/数量列
   显示 `H_合` / `L_组`（只读，由组员推导）。父节点**不产生任何工程量行**，
   在汇总 / 导出 / 详情面板中仅作为下属子构件工程量的合计分组行。
3. **子节点行**：主表格「沟槽围护原则」列显示**右侧原则名**；「地基处理」
   「降水措施」「工作面宽」各自可选。「围护原则」tab 中：
   * 「左侧围护」行置灰（由父节点/左侧相邻构件的右原则接管）；
   * 「挖填类型」「管道基础」取侧下拉编组时自动置"按右侧原则"，左选项置灰；
   * 「左侧支撑」「右侧支撑」勾选均有效，语义 = 该构件**左 / 右面的支撑**：
     构件 1 的左侧支撑控制左边坡支撑；构件 i 的右侧支撑控制其右面（中间坡 /
     右边坡）的支撑；中间坡挂深侧构件时由深侧构件朝向该面的勾选控制（§6.3）。
4. **成员维护**：右键「加入合槽…」「移出合槽」（恢复为普通构件或单管分设）、
   「解散合槽」（父节点删除、子节点还原）；组内上移/下移 = 左移/右移
   （复用现有 move_element 交互）。
5. **断面图**：选中父节点或任一子节点均画**整槽全景断面**（左边坡 + 各构件本体 +
   中间坡/净距 + 右边坡），见 §7。

## 5. 数据模型

```
element 增列:
  pe_left_name     String(200)  左侧围护原则名（空 = 普通单原则模式，现状语义）
  pe_right_name    String(200)  右侧围护原则名
  support_left     Boolean      左侧支撑是否计算，默认 True
  support_right    Boolean      右侧支撑是否计算，默认 True
  excvt_side       String(1)    挖填类型取侧 "L"/"R"，默认 "L"
  foundation_side  String(1)    管道基础取侧 "L"/"R"，默认 "L"
  group_id         -> trench_group.id   nullable；组内 order_no 即左右顺序

trench_group（父节点）:
  id, unit_id(FK), name, order_no,
  pe_name          # 左边缘围护原则
  pw_name          # 左边缘工作面宽原则
```

* **占位机制**：左右分设模式下 `pe_name` 存 `LR_PE_TEXT = "左右分设"`（新常量，
  对应已删的 1.0 `MULTI_PE_TEXT = "多围护原则"` 先例）；`resolve_element_principles`
  的按名回退逻辑跳过占位名，改读左右列。
* stn JSON 体版本 2 → 3：element 新列 + `trench_group` 表 + `group_id`，全部可缺省
  （读 v2 文件 = 无分侧无编组，行为不变）；编解码器同步。
* undo 是整工程快照，新表/新列随快照复制（补一条含新列的回归用例）；
  锁/备份/自动保存不受影响。
* **原则库（PE/PF/PP/PW 表结构）与 FormPE 编辑器零改动**——分侧只是引用方式变化，
  这是构件级方案相对做法级方案的最大工程红利。

## 6. 计算引擎

### 6.1 库公式 `sides` 变量（贯穿两个场景）

Ei 库模板全部 `*2` → `*sides`（喷锚 FA~FD、横列板/灌注桩/SMW 的 F 与围檩项；
放坡模板本就无公式）；`engine.pre_sub` 增加第四代入变量（公式无该变量时零影响）：

* 普通构件：`sides=2` 代入，输出算式里就是 `*2`，**与现状逐字节一致**；
* 分侧/合槽的每个面：`sides=1`，得单面量；
* 存量工程公式（用户副本仍带 `*2`）不自动改写：普通模式语义本就两侧、照旧正确；
  左右分设是**新建引用**（从库模板语义出发），见 §6.2 的取值路径。

### 6.2 单管左右分设

* **两侧独立选做法**：`choice_work(pe_left, groove_depth)` 与
  `choice_work(pe_right, groove_depth)` 各自进行（同一深度）。
* **不对称几何**：梯形 `(2B + H*sL + H*sR)*H/2`；层间外扩 `Δ*sL + Δ*sR`；平台加宽
  只加发生切级的一侧；层循环按**两侧级标高的并集**切段，每段 `(sL, sR)`；
  挖方段合并判据从"坡度相等"改为"(sL,sR) 相等"。`trapezoid_expr` 直壁侧省略该项
  （右侧桩：`(2*B+H*0.5)*H/2`；两侧直壁仍 `B*H`）。普通构件走原单套循环路径，
  逐字节不变（两条路径共用底层梯形函数）。
* **公共参数取侧**：开挖土质/回填材质取 `excvt_side` 侧 PE；砼基础/基础角度/垫层取
  `foundation_side` 侧 PE，**图集查询与候选参数匹配（match_atlas_candidates）
  同用该侧**。
* **F 类（围护量）**：每侧 work 的各级构件 + 止水各调一次，`sides=1`；
  放坡侧模板无公式，天然不出量。
* **Z 类（支撑/围檩）**：`support_left` 勾选 → 左侧 work 的 Z 公式参与（`width`
  代入槽底宽 B、`sides=1`）；`support_right` 同理。两侧都勾且两 PE 相同 = 现状
  两侧总量，数值自洽。
* **换填层**（用户强调点）：PF 换填层的梯形同层循环取 `(sL, sR)`——换填层开挖/
  回填量自动反映两侧不同放坡系数。
* **降水 / 特殊地基**：`pp` 原则不变（井型"侧数"参数由用户按实际布置设置）；
  特殊地基公式 `width=B` 不变。湿土排水的 `cal_groove(depth-1)` 副调用自动
  继承不对称几何。

### 6.3 合槽编组

**几何（区间模型，从左到右拼接）**：

```
B_平底 = wL + Σ b_i + Σ g_i(i=1..n-1) + wR
  b_i  = 构件 i 基础外皮宽（= 单管槽底宽去掉两侧工作面，同原合槽稿 §5.1）
  wL   = 父节点 PW 工作面宽度表值（按构件 1 管材/管径查）
  g_i  = 子节点 i 的 PW 工作面宽度表值（按构件 i 管径查）= 与右侧相邻构件的间距
  wR   = 子节点 n 的 PW 表值（按构件 n 管径查）
H_i    = 构件 i 的槽底深（埋深 + 换填 + 壁厚 + 垫层，各自推导）；H_合 = max H_i
```

* **等深**（所有 H_i 相同）：整槽一个大梯形——左坡取父 PE 做法、右坡取子 n 右 PE
  做法（均按 H 选做法），中间平底宽 `B_平底`；
* **异深（中间坡模型，取代原稿"统一槽底+超挖回填"）**：各构件挖至各自 H_i；
  相邻埋深差 ΔH_i 在间距 g_i 区间内形成**中间坡**——坡高 ΔH_i、坡度/做法取
  `choice_work(子i右PE, ΔH_i)`（按坡高选做法；放坡时水平投影 ΔH_i×s 占用 g_i，
  `g_i < ΔH_i×s` 时黄色预警）；右 PE 为桩类时中间坡为竖直隔断墙（真实工程
  "深浅槽间钢板桩分隔"场景）。等深构件间 ΔH=0，纯净距矩形；
* **分层回填**：沿用原合槽稿 §5.2 的**并集分层 + 功能带高要求优先**（坞膀 >
  管顶50 > 覆土），材质来源改为各构件 `excvt_side` 侧 PE、边缘区随边缘 PE；
  挖方土质同理按区间取（同土质 QDict 同 key 自动合并）。

**公式量（每面 ×1）**：左边坡（父 PE 做法）的围护量挂**构件 1**；中间坡 i 挂
**深度更深一侧的构件**（H_i 与 H_{i+1} 较大者，等深无坡无归属问题）；右边坡挂
**构件 n**。`sides=1`、`width` 代入 `B_平底`（对顶支撑类 width 语义三期细化）。

**降水**：**逐构件计算、挂各自名下**（井数 = ceil(L_组/井距)×侧数，L_组 =
组员 amount，编组校验一致），不做整槽单次计算、不去重。组员引用同一条 PP 时
井数会重复（×n）；需要整槽只算一次时，由用户自建一条**"空降水原则"**
（全部井型深度阈值设为不启用即可，现状数据模型已支持），只让一条构件选实际
降水原则、其余组员选空原则。

**换填**：子节点 PF 只作用于自身横向范围（`b_i` + 平分到的间距），矩形断面，
材质/厚度按各自 PF（取代原稿"组内统一"）。

**工程量归属（横向区间切分，评审定案：所有工程量都分到构件名下，父节点零工程量）**：

```
挖方/回填：左工作面区 → 构件 1；右工作面区 → 构件 n；
          中间区 g_i → 构件 i 与 i+1 平分；本体区 b_i → 构件 i
围护量：  左边坡 → 构件 1；中间坡 i → 深侧构件；右边坡 → 构件 n
逐管量：  垫层/基础/包封/箱涵本体/管材/扣减 → 各构件（现状函数不动，同 key 负项合并）
降水：    逐构件、挂各自名下（含湿土排水，同一规则）
```

每条构件量 = 自身名下区间之和 × L_组。父节点不产生任何工程量行，在汇总 / 导出 /
详情面板中仅作为**下属子构件工程量的合计视图**（分组行，项目特征 = 组名 + 成员
规格串）。算式不做预运算：`B_平底` 把 `wL / Σb / Σg / wR` 的查表来源全部写全
（注意 mm/m 混算教训，`works_quantities` width 修正史）。

**支撑勾选（合槽内）**：语义统一为"该构件左 / 右面的支撑"——构件 1 的左侧支撑
→ 左边坡支撑（父 PE 做法的 Z 公式）；构件 i 的右侧支撑 → 其右面（中间坡 i，
构件 n 时为右边坡）的支撑；中间坡 i 挂深侧构件，其支撑由深侧构件**朝向该面的**
勾选控制（深侧为 i 时用 i 的右侧支撑，深侧为 i+1 时用 i+1 的左侧支撑）。

## 9. 校验规则

1. 左右分设：两 PE 必选；「左右分设」占位名不可作为左/右原则；支撑允许全不勾
  （= 无支撑量）；
2. 编组：组员 ∈ {直埋、包封、箱涵、管廊}（顶管/牵引管/构筑物拒绝）；同一单位
   工程内；组员 ≥ 2；组员 amount 一致（否则拒绝并提示先统一——"局部合槽/起止
   桩号不同"列远期）；
3. 父节点 PE/PW 必选；子节点右 PE/PW 必选；
4. 中间坡 `g_i < ΔH_i×s` 时黄色预警（不阻断，用户自行加大间距或改桩）；
5. 面宽原则的"沟槽宽度表"模式（groove_width==B）不适用于间距/边缘工作面
  （表值是单管槽宽语义），合槽一律查工作面宽度表（文档与 UI 提示）；
6. 合槽内子节点左原则、挖填/基础"按左侧"选项置灰（左面围护由父节点 / 左邻
   构件的右原则接管）；左 / 右支撑勾选均有效（语义 = 该构件左 / 右面的支撑，
   见 §6.3）；移出合槽后恢复可编辑。

## 11. 已定案与待决策点

**评审已定案（2026-10-25，正文按此撰写）**：

1. **合槽降水**：逐构件计算、挂各自名下，不做整槽单次计算、不去重；需要整槽
   只算一次时，用户自建"空降水原则"（全井型不启用）分配给组员（§6.3）；

   仅作子构件合计视图（§6.3）；
3. **中间坡**：围护量计入**深度更深一侧**的构件；做法按**坡高 ΔH** 选择（§6.3）；
4. **间距**：g_i 由子节点工作面宽原则匹配到的表值确定，即当前构件与右侧相邻
   构件的间距（§6.3 几何）。

## 12. 风险

* **公式改版回归**：库模板 `*2`→`*sides` 后，普通构件输出算式必须与现有基线
  逐字节一致（`tests/baselines/对拍工程.json` 全量对拍 + `sides` 代入单测）；
* **几何双路径退化一致性**：普通构件走原单套循环、分侧才走并集路径，两路径共用
  底层梯形函数，浮点递推顺序保持一致；
* **主表格树形化是 UI 大改**：现平铺 `ElementRow` 源要混排 `trench_group` 父行 +
  缩进子行 + 折叠，选中/右键/移动/复制原则等既有交互都要适配父子结构；
* **B_平底 算式长度**：全来源展开（wL/Σb/Σg/wR + 两侧坡）后算式很长，与现有
  `Dim` 拼法一致性、Excel 可粘贴性需对拍；
* **异深中间坡几何**是本计划最复杂的一块（槽底折线 + 分层并集 + 坡侵占校验），
  放三期，二期等深先把区间模型跑通；
* **无 1.0 对拍**：一/二期各配 2~3 个手算断面金样例（单管左坡右桩、双管等深
  合槽、双管异深中间坡）；
* **父节点零工程量约束**：`compute_group` 的输出直接按构件分桶，汇总 / 导出 /
  详情面板各处不得给父节点挂量（父行只是合计视图）——实现时以"父节点无
  QDict 行"作为硬校验；
* **合槽路径完全独立**：`compute_element` 单构件路径逐字节不变（对拍现有回归样例）。
