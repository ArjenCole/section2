## 0. 一句话结论

**图集里有外径数据，但不是每张表都有；没有任何一张表有独立的“内径”列。**
10 张管道图集表中，5 张有独立的 `oD`（外径）列，另外 5 张只有 `D`（管径）和 `t`（壁厚）；
内径要么就是 `D` 本身（当 `D` 定义为内径时），要么要用 `oD-2t` 或 `D-2t` 推算。

**构件库本身没有存外径/内径**：`EleInventory.json` 的管道行只有
`mat / cat / dn / content / t`，旧版 `EleInventory.stn` 只有 `Mat / Dn / Content`。
当前程序统一按 `od = dn + 2t` 推算外径；这只对“D=内径”的管类成立，
对 PVC-U、PE、球墨铸铁、钢管等“D=外径/公称直径”的管类会偏大或偏小（详见第 5 节）。

### 4.1 一句话记忆

- **D 是内径**：混凝土管、混凝土顶管、HDPE 缠绕、PVC-U 加筋、PE 缠绕 A/B → `ID=D`，`OD=D+2t`；
- **D 是外径**：PE 给水管/定向钻 → `OD=D`，`ID=D-2t`；
- **D 是公称外径、另有 oD**：PVC-U 双壁波纹/平壁、PE 双壁波纹、钢带 PE → `OD=oD`，`ID≈oD-2t`；
- **D 是公称直径 DN、另有 oD**：球墨铸铁、钢管 → `OD=oD`，`ID=oD-2t`。

## 6. 改造前实现里的问题（存档，均已修复）

> 本节与 §7 是改造前的排查记录，时态保留"当时"口径；每条问题后注明修复落点。

### 6.1 构件库只存了 `dn` 和 `t`，没存 `od` / `id`

`EleInventory.json` 的管道行结构：

```json
{"mat": "...", "cat": "...", "dn": 600, "content": "1",
 "t": {"con90": 60, "con120": 60, "...": null}}
```

当时 `scripts/build_element_inventory.py` 只把图集的 `t` 快照进 JSON，
没有把 `oD` 一起存下来。旧版 `mcAtlas.cs` 是能读到 `oD` 的（第 274 行），
旧版 `mcE1.cs` 也算的是 `At.oD > 0 ? At.oD : Dn + 2t`（第 65 行）。
当时新版在 `services/atlas.py` 的快照路径里直接返回 `od=dn+2t`，
把图集 `oD` 丢掉了。
**修复**：构件库 v3 起管道行带 `od` / `id` / `direct`（图集直取对，见 §3 注），
`build_element_inventory.py` 快照时按 `AtlasCatalog.read` 的直取对只存图集
给出的两个值（生成脚本 `pipe_diameters` 段）；`core/pipe_dimensions.py`
专管三直径换算口径。

### 6.2 `dn` 被统一当成“管道内径”

当时 `core/calc/engine.py` 把 `info.pipes[0].dn` 标成“管道内径”，
又用 `dn + t*2` 当外径。对混凝土管、顶管、HDPE 缠绕是对的；
对 PE 给水管（`D` 是外径 De）、PVC-U/PE 双壁波纹（`D` 是公称外径）、
球墨铸铁/钢管（`D` 是 DN）就不对。第 5 节的偏差就是由此产生的。
**修复**：`dn` 只作名义规格与图集查表键，几何一律用图集直取的 `oD` / `iD`
（`engine.atlas_dims`，`engine.pipe_id_dim` 按直取对标注内径来源）。

### 6.3 给水钢管被误按“无缝钢管”级别查

当时的 `services/atlas.py` 钢管分支：

```python
elif "钢管" in mat:
    tmp_level = "给水钢管"
    if query.size_b <= 0.15:
        tmp_level = "焊接钢管1.0Mpa"
    else:
        tmp_level = "无缝钢管"
    if "焊接" in mat:
        ...
    elif "无缝" in mat:
        tmp_level = "无缝钢管"
```

旧版 C# 的 `else` 分支会把“给水钢管”还原成 `给水钢管`，当时新版少了这个
`else`。结果：

- 给水钢管 DN700~2000 在“无缝钢管”表里没有行 → 壁厚为空（9 行）；
- DN150、DN350、DN400~600 取到了无缝钢管的壁厚（如 DN400 取 9 mm，给水钢管应为 10 mm）；
- 图集“给水钢管”级别其实有 DN80~2000 的完整数据，**不是图集缺数据，是代码查错级别**。

**修复**：`atlas.py` 的钢管分支已补齐给水钢管兜底（`elif "无缝"` 之后还原
`给水钢管`，现位于 `atlas.py` 钢管段），并重新生成构件库快照。

### 6.4 其他数据质量问题

- **PE 缠绕 A/B 型壁厚对调**：当时 `services/atlas.py` 的条件是
  `"B" in mat → A型，否则 → B型`，与构件库名称相反。A/B 壁厚并不总是相同
  （如 DN150、DN400、DN700 就不同），构件库里 A 型拿到了 B 型的壁厚（反之亦然），
  DN450~600、800 以上多数规格相同，所以不是每个管径都能看出来。
  **修复**：`atlas.py` 已改为按“缠绕”级别判断（`D_KIND` 口径，`"缠绕" in level → A/B`），
  与构件库命名一致。
- **PVC-U DN1000 的 `oD` 疑似录入错误**：`06MS201-2.xlsx` 中 DN1000 双壁波纹管
  `oD=1103.0`，按同表规律应在 1003 左右；如果直接改用 `oD`，这一行会引入约 100 mm 的误差。
- **06MS201-1 砼基础表有重复行**：例如Ⅱ级 DN600、120° 同时有 `t=60` 和 `t=65` 两行，
  程序按“最后一条命中”取值；用之前建议核对图集，确认哪一行适用于当前管级别。
- **2 行残留模板**：双插口/钢承口顶管里的 `Ⅱ级混凝土管 DN600`，构件类别为空，建议删除。
- **包封 BWFRP 没有图集表**：程序按包封构件参数算，壁厚为空/按 0 处理；如果以后要算 BWFRP 的
  外径/内径，需要补一张管材规格表。
- **两个 PDF 是扫描件**：`04S516` 和 `06MS201-2` 都提取不到文字（扫描图），不能直接检索；
  目前程序用的是 xlsx 数字化表。
